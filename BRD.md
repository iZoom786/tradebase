# Business Requirements Document (BRD)

## Project: Tradebase AI Platform
**Version:** 1.0.0  
**Date:** July 2026  
**Status:** Approved Baseline  

---

## 1. Executive Summary
Tradebase is an event-driven, low-latency, machine-learning-powered trading platform that specializes in delivering real-time currency feature streams ($EUR/USD$, etc.) and premium execution signals to algorithmic traders. The platform monetizes high-performance analytics pipelines by providing tiered data subscriptions via real-time streaming APIs. Additionally, Tradebase lowers the retail barrier to entry by offering a transparent, live-updating paper trading sandbox starting with a $100 virtual equity baseline.

## 2. Business Objectives & Goals
*   **Monetization via Data-as-a-Service (DaaS):** Generate recurring revenue by charging algorithmic developers monthly subscriptions for direct API access to clean, pre-calculated features and indicators.
*   **Convert Free Trials with High Trust:** Eliminate retail developer skepticism by maintaining a public, unalterable 1-minute forward-testing (paper trading) model.
*   **Establish a Closed-Loop Feedback Engine:** Build an autonomous framework that utilizes live trading performance metrics to dynamically adjust and retrain background machine learning algorithms.

## 3. User Personas & Target Market
*   **Retail Algorithmic Traders:** Technical traders looking for turnkey, high-quality data pipelines (indicators + sentiment metrics) to drive their own Python scripts or MetaTrader 5 (MT5) Expert Advisors.
*   **Premium Quant Subscribers:** Institutional or advanced hobbyist traders buying high-probability trade direction signals generated by proprietary ML models.
*   **Trial / Evaluator Users:** Web visitors tracking the platform's accuracy via a risk-free, transparent virtual portfolio.

---

## 4. Functional Requirements

### 4.1 Monetization & Tiered Subscriptions
The platform must enforce strict, automatic data gating based on the subscriber's paid billing tier using native messaging broker authorization controls.

| Tier | Accessible Data Types | Target Subject | Delivery Mechanism |
| :--- | :--- | :--- | :--- |
| **Basic (Paid)** | Raw OHLC, Pre-calculated technical indicators, Time-decayed sentiment scores | `tradebase.forex.*.raw.1m` | NATS Client Connection |
| **Premium (Paid)**| Basic Tier + Machine Learning Direction Signals + Confidence Probabilities | `tradebase.forex.*.prediction.1m` | NATS Client Connection |
| **Trial (Free)** | Visualizations of current paper trade entries, exits, and equity graphs | Web Dashboard | Secure Server WebSocket |

### 4.2 Transparent Paper Trading System
*   The system must run a continuous virtual execution loop starting with a strict balance of **$100.00 USD**.
*   Simulated executions must trade static micro-lots (0.01 lots) to ensure realistic risk management for a small capital profile.
*   The performance history must generate a live equity curve graph embedded directly into the public website.
*   Free-tier users must have access to a "Reset Balance" utility to restart their virtual profile back to $100.00.

### 4.3 Machine Learning Feedback Loop
*   The platform must track rolling performance metrics (Win Rate, Log Loss, Profit Factor, Max Drawdown).
*   If live performance metrics drop below predefined risk thresholds, the system must trigger automated safeguards (e.g., risk-reduction or early model retraining).

---

## 5. Non-Functional Requirements
*   **Latency:** Core data publishing from candle close to NATS subject dispatch must occur under sub-millisecond conditions.
*   **Scalability:** The central NATS broker cluster must handle thousands of concurrent authenticated client connections without degradation.
*   **Security:** Authentication must be cryptographic, decentralized, and validated at the broker boundary via NATS JWTs to preserve processing throughput.
